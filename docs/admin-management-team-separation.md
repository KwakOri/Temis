# 관리자 메뉴 및 팀 관리 분리

## 팀 관리 검토와 결정

레거시와 Studio 엔진은 `teams`, `team_members`, 사용자별 주간 일정을 공유한다.
레거시 템플릿은 `relations_team_template_and_team`, Studio 템플릿은
`team_studio_connections`에서 각각 팀을 연결한다.

API 주소나 화면만 분리해도 팀·멤버가 독립되는 것은 아니다. 사용자 선택에 따라
팀과 멤버는 공유하는 혼합 방식을 유지하고 공통 `TeamManagement` UI에 조회 범위를 전달한다.

| 연결 상태 | 레거시 팀 관리 | 새 에디터 팀 관리 |
| --- | --- | --- |
| 레거시 연결만 있음 | 표시 | 제외 |
| Studio 연결만 있음 | 제외 | 표시 |
| 양쪽 연결 있음(혼합) | 표시 | 표시 |
| 연결 없음 | 표시 | 표시 |

`GET /api/admin/teams?scope=legacy|studio`가 서버에서 목록을 분류한다.
기존 범위 없는 조회는 전체 팀을 반환해 양쪽 템플릿 연결 화면에서 기존 팀을 선택할 수 있다.
혼합 팀의 이름·멤버·활성 상태 변경과 팀 삭제는 양쪽 엔진에 적용된다.
엔진별 멤버가 달라야 할 때는 팀을 별도로 생성한다.
연결 변경 후에는 팀 목록 캐시를 무효화해 분류를 갱신한다.
목록 분리 자체에는 추가 스키마 변경과 데이터 이관이 필요하지 않다.
새 에디터 팀 연결에는 기존 `20261005000000_create_team_studio_connections.sql`
마이그레이션이 선행되어야 한다. 연결 테이블이 없으면 API는 기존 팀 목록과
`studioConnectionsAvailable: false`를 반환하고 화면에 DB 업데이트 필요 안내를 표시한다.
권한·네트워크 오류와 기존 팀/레거시 테이블 오류는 빈 목록으로 숨기지 않는다.

## 함께 적용한 변경

- 맞춤 주문은 썸네일·시간표 내부 탭으로 분리하고 탭별 조회 조건을 유지한다.
- 같은 상태 필터·정렬·10건 페이지 이동을 사용한다. 기본 제작 대기는 완료·취소를 제외한다.
- 레거시 메뉴에 기존 템플릿 관리·썸네일 관리·팀 템플릿·에셋·레거시 팀 관리를 모은다.
  기존 템플릿 목록은 `engine=legacy`로 조회하며 공개·비공개 개수도 동일 범위로 집계한다.
- 기존 `/admin/templates`, `/admin/teams`, `/admin/thumbnails`, `/admin/team-templates`,
  `/admin/legacy-template-assets` 주소는 해당 내부 탭을 표시한다.
- 새 `/admin/studio-templates` 템플릿 관리 메뉴에서 시간표·팀시간표·썸네일을 전환한다.
  시간표가 기본이며 `section=timetable|team|thumbnail`로 직접 접근한다.
  기존 각 Studio 목록 주소도 같은 화면의 해당 탭을 표시한다. 생성·편집·미리보기
  주소는 유지하며, 개인 시간표와 팀 시간표는 기존 API의 `mode` 필터로 구분한다.
- Studio 목록은 대표 이미지·이름·게시 상태·개인/일반 종류를 한 영역에 표시하며 ID와
  자동 미리보기 상태 문구는 숨긴다. 세 Studio 탭의 정보 수정 모달에서 이름·대표 이미지·
  개인/일반 종류를 저장한다. 이미지가 없으면 자동 미리보기를 사용하며, 업로드·제거는
  저장할 때 적용한다. 단계별 저장 중 오류가 발생하면 성공한 변경을 안내하고 다시 시도한다.
- 일반 템플릿·레거시 썸네일 목록에서도 이름을 수정할 수 있다.
  판매 가격·상품 설명 등은 기존 상품 편집에서 관리한다.
- 템플릿 Hub는 템플릿 판매 관리 화면으로 구성한다. 버전 필터는
  스튜디오·레거시·전체 순서이며 최초 진입 및 초기화 기본값은 스튜디오다.
  상품·가격, 판매 준비 항목과 판매 시작/중지를 우선 표시하고 제작 작업은 접어 둔다.
  `salesType=general`로 조회해 이미 일반 템플릿인 항목만 표시한다. 개인·일반
  전환은 시간표·팀시간표·썸네일 Studio 목록과 레거시 템플릿 관리에서 수행한다.
  전환 후 관련 목록 캐시를 갱신하며 판매 중인 항목의 개인용 전환은 판매 중지 후 가능하다.
  종류 필터는 시간표·썸네일·팀 시간표·전체 순서이며 기본값은 전체다.
  `20261006000000_add_template_hub_category.sql`이 조회 뷰에 분류를 추가해
  종류 필터·개수·페이지 이동을 DB에서 처리한다. 게시 문서를 우선하고 게시 문서가
  없으면 최신 초안의 팀 레이아웃으로 시간표와 팀 시간표를 구분한다.

## 검증

- `npx tsc --noEmit`
- `npm run lint` (기존 경고 포함)
- `node --import tsx scripts/check-admin-management.ts`
- `node --import tsx scripts/check-admin-team-list.ts`
- `node scripts/check-template-hub-sales-browser.mjs` (API 테스트 응답만 사용)
- 로컬 Next 개발 서버에서 `node scripts/check-admin-management-browser.mjs`

브라우저 검사는 모든 API를 테스트 응답으로 대체한다. 주문 조건·페이지 유지,
키보드 탭 전환, 레거시 메뉴, 팀 범위, 이름 저장·빈 이름 검증·실패 후 재시도,
모바일 화면 및 개인·일반 전환과 판매 중 전환 거부/재시도를 검증하며 실제 DB에 쓰지 않는다.
